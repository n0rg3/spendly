# @spendly/serverless — API чеков на Vercel

Автономная бессерверная функция: сама ходит на `suf.purs.gov.rs` и передаёт сырой текст
чека в Gemini 2.5 Flash. Весь разбор позиций, итог, дата и автокатегоризация выполняются
ОДНИМ вызовом LLM со `responseSchema` (Structured Outputs / JSON Mode) — на сервере нет ни
регулярных выражений для позиций, ни словарей-фолбэков, ни кэша «товар -> категория».
Локальный компьютер и ngrok не нужны — GitHub Pages обращается к публичному HTTPS-адресу Vercel.

## Как это работает

1. Функция скачивает страницу чека по `qrUrl` (валидация: только `https` и `*.purs.gov.rs`);
   на транзиентный сбой — один быстрый повтор.
2. Вырезает из HTML видимый текст (без `<script>`/`<style>`) — это «сырой текст чека».
3. Отправляет его в Gemini 2.5 Flash вместе со списком категорий пользователя и схемой ответа.
4. Модель возвращает строгий JSON — позиции, категорию каждой позиции, дату и итог чека.
5. Функция приводит числа к `number` и оставляет только категории из списка пользователя,
   сопоставляя названия нормализованно (регистр/пробелы/NFKC) и отдавая написание пользователя.

## Почему категории раньше определялись «со 2-3 раза» и что сделано

Mini App передаёт в запросе `categories` из своего дашборда. Если скан уходил раньше, чем
Firestore отдавал дашборд, список категорий был пустым → функция подставляла свой список,
и названия категорий не совпадали с категориями пользователя (позиции приезжали без
категорий). Дополнительно первый «холодный» запрос к сайту чека/Gemini иногда падал —
пользователь сканировал заново, и со второго раза всё работало.

Что делает клиент (`apps/mini-app/src/main.tsx`):

- ждёт категории пользователя через ref на дашборд (без «устаревшего» state);
- **никогда не отправляет пустой список**: если дашборд не пришёл за 5 с, уходит стартовый
  список текущего языка — ровно те же названия, что лежат в Firestore у нового пользователя
  (`defaultDashboard`), плюс `lang` в теле запроса;
- отменяет предыдущий незавершённый запрос через `AbortController` (ответ гонки не перезаписывает свежие данные);
- дебаунсит повторные срабатывания QR-сканера (300 мс) и блокирует повторные запуски, пока идёт распознавание;
- обновляет позиции и их категории одним `setState` (атомарно);
- сопоставляет категорию от модели с категорией пользователя нормализованно (регистр, пробелы, NFKC).

Что делает функция (`api/parse-receipt.js`):

- держит fallback-список **синхронным с клиентом** (`DEFAULT_CATEGORIES_BY_LANG`: ru/en/sr) и выбирает его по `lang`;
- повторяет один раз транзиентные сбои: скачивание страницы чека (таймаут 20 с) и вызов Gemini
  (5xx/429/сеть), поэтому первый сбой не требует повторного сканирования;
- сравнивает категории от модели с категориями пользователя нормализованно
  (регистр/пробелы/NFKC), а в ответе отдаёт написание пользователя.

Диагностика: `[AI Parse Sent]` / `[AI Parse Received]` в консоли Mini App и предупреждение
`parse-receipt: клиент не передал categories — беру стартовые категории языка «…»` в логах функции.


## Эндпоинт

```
POST https://<project>.vercel.app/api/receipts/parse
POST https://<project>.vercel.app/api/parse-receipt   (тот же handler, алиас из vercel.json)
```

Запрос:

```json
{ "qrUrl": "https://suf.purs.gov.rs/v/?vl=...", "categories": ["Еда", "Транспорт"], "lang": "ru" }
```

`categories` опциональны: Mini App всегда передаёт свои (или стартовый список языка), а функция
использует их как fallback по `lang`, если список всё-таки пустой:

| `lang` | Fallback-список (совпадает с новым пользователем в Mini App) |
| --- | --- |
| `ru` (по умолчанию) | `["Еда", "Транспорт", "Покупки"]` |
| `en` | `["Food", "Transport", "Shopping"]` |
| `sr` | `["Hrana", "Prevoz", "Kupovina"]` |

Именно этот список уходит в схему ответа модели (`enum`), поэтому Gemini всегда выбирает
категорию только из категорий пользователя (или `null`, если ничего не подошло).

Ответ `200` — ровно тот JSON, который по схеме возвращает модель:

```json
{
  "dateTime": "2026-09-16T17:50:44",
  "items": [{ "name": "VODA MINERALNA 0,5L", "qty": 1, "price": 57.99, "total": 57.99, "category": "Продукты" }],
  "total": 377.96
}
```

`dateTime` — ISO 8601 (клиент показывает дату чека в модалке и берёт её как дату расходов).

Ошибки: `{ "error": "..." }`

| Статус | Когда |
| --- | --- |
| `400` | нет `qrUrl` / некорректный или чужой URL (не `*.purs.gov.rs`) |
| `405` | метод не `POST` |
| `422` | страница получена, но текст пуст или модель не нашла ни одной позиции |
| `502` | сайт чека недоступен / вернул ошибку, либо Gemini вернул ошибку |
| `503` | не задан `GEMINI_API_KEY` — распознавание недоступно |
| `500` | внутренняя ошибка |

Без AI разбора больше нет: если ключ не задан или Gemini недоступен, функция честно
возвращает ошибку, а не «пустой чек» — позиции с `category: null` приходят только тогда,
когда модель реально не подобрала категорию.

## Деплой

```bash
cd apps/serverless
npx vercel login
npx vercel --prod          # выдаст https://<project>.vercel.app
npx vercel env add GEMINI_API_KEY production   # вставить ключ из https://aistudio.google.com/apikey
npx vercel --prod          # передеплой, чтобы переменная подхватилась
```

Затем в `apps/mini-app/.env`:

```
VITE_API_URL=https://<project>.vercel.app
```

и пересборка мини-аппа (`pnpm --filter @sp3ndly/mini-app build`), после чего `dist` публикуется
на GitHub Pages. Всё — без ngrok и без запущенного локального сервера.

## Переменные окружения

| Переменная | Обязательна | Описание |
| --- | --- | --- |
| `GEMINI_API_KEY` | да | Ключ Gemini (https://aistudio.google.com/apikey). Без него распознавание чеков недоступно (503). |
| `GEMINI_MODEL` | нет | По умолчанию `gemini-2.5-flash` — модель с поддержкой Structured Outputs (`responseSchema`). |
| `ALLOWED_ORIGINS` | нет | Доп. CORS-источники через запятую. |
| `GEMINI_BASE_URL` | нет | Только для тестов — подмена базового URL Gemini (стаб/прокси). |
| `RECEIPT_RETRY_DELAY_MS` | нет | Пауза между повторными попытками при транзиентном сбое (по умолчанию 500 мс; `0` — без паузы, используется в тестах). |

## CORS

По умолчанию разрешены `https://n0rg3.github.io`, `http://localhost:5173`, `http://127.0.0.1:5173`.
Запросы без `Origin` (curl, Telegram-клиент) проходят. Источники из белого списка получают
`Access-Control-Allow-Origin` со своим значением; чужим доменам заголовок не отдаётся — браузер
блокирует запрос.

## Локальная проверка функции

```bash
cd apps/serverless
pnpm test               # автотесты на node:test (ответ модели, схема, категории, ретраи, CORS, SSRF, статусы) — сеть не нужна
pnpm check              # синтаксис функции
npx vercel dev          # http://localhost:3000/api/receipts/parse
```

Проверка защиты от SSRF (должно вернуть 400):

```bash
curl -s -X POST http://localhost:3000/api/receipts/parse \
  -H 'Content-Type: application/json' \
  -d '{"qrUrl":"https://evil.com/steal"}'
```

Тесты используют фикстуру `test/fixtures/receipt.html` и подменяют `fetch`: и запрос к сайту
чека, и вызов Gemini отдаёт мок, поэтому реальная сеть и API-ключ не нужны.

## Безопасность

- URL чека валидируется: только `https:` и только домены `*.purs.gov.rs` (защита от SSRF).
- Таймаут запроса к сайту чека — 20 секунд, одна быстрая повторная попытка на транзиентный сбой.
- Ключ Gemini живёт только в env Vercel — в клиентский бандл не попадает.

## Примечание про парсинг

Страница чека отдаётся без отрендеренной таблицы (её рисует Knockout.js на клиенте), поэтому
функция берёт текстовый дамп чека из `<pre>` панели `#collapse3` (fallback — `#PrintInvoice`
и `body`) и передаёт его модели. Название товара может быть на отдельной строке от чисел
`<цена> <кол-во> <итог>` — такие случаи разбирает LLM, а не серверные регулярки. Логика 1:1
повторяет `apps/api/src/index.ts`.

## Формат ответа модели (responseSchema)

Модель всегда возвращает объект строго такого вида (JSON Mode, `temperature: 0`):

```json
{
  "dateTime": "2026-09-16T17:50:44",
  "items": [
    { "name": "BOMBONE HARIBO STAR MIX", "qty": 1, "price": 134.99, "total": 134.99, "category": "Продукты" }
  ],
  "total": 194.98
}
```

- `items` — все позиции чека: `name`, `qty`, `price` (за единицу), `total` (по позиции), `category`.
- `category` — только значение из списка пользователя (`enum` в схеме) либо `null`.
- `dateTime` — ISO 8601; `total` — итог чека.
